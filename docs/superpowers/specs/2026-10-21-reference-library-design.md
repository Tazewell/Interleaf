# Reader 独立文献管理与 LaTeX 引用：第一阶段设计

日期：2026-10-21。状态：已批准并实施（2026-10-22）；最终整体验证与人工桌面验收由交付流程记录。

## 1. 已确认的方向与本稿的建议

用户希望 Reader 独立替代 Zotero，写作使用 LaTeX / Overleaf，现有文献以 PDF 为主。

本阶段完成「导入 PDF → 整理论文信息 → 阅读、翻译和笔记 → 收集写作参考文献 → 导出稳定的 .bib」这一条完整流程。以下范围、默认行为和实现边界为已批准方案。操作入口与人工验收步骤见 [文献库与 LaTeX 引用](../../reference-library.md)。

成功标准是：用户能只使用 Reader 管理论文和生成参考文献库；调整论文信息、重复导入文件或重新导出时，不会无意改变已经用于 LaTeX 的引用键；现有阅读数据不丢失。

## 2. 现有能力与实际缺口

现有功能应直接复用：

- PDF / EPUB 导入、解析、阅读、翻译、批注、笔记及本地桌面启动。
- 导入论文后从 PDF 前两页检测 DOI / arXiv 编号，查询文献信息；按标题查询已有手动入口。
- 元数据记录来源，在线查询不覆盖手动修改。
- 基于 DOI、arXiv 编号和规范化标题的疑似重复分组，以及人工合并和标记非重复。
- 论文文件夹、标签及 BibTeX、RIS、CSL-JSON 导出。

主要缺口：

- 文献和文件目前共用 Document；无法自然表达没有 PDF 的文献，或者一篇文献拥有多个独立附件。
- 引用键由前端在导出时生成，重名后缀取决于当前导出批次，不能保证长期稳定。
- 没有通用 .bib 导入、BibLaTeX 导出模式和持续更新的本地导出目标。

代码依据：`packages/reader-core/src/index.ts`、`apps/server/internal/reader/metadata_lookup.go`、`metadata.go`、`merge.go`、`apps/web/src/papers/model.ts`、`citation.ts`。

## 3. 第一阶段范围

### 3.1 文献与附件

- 新增独立 PaperItem，保存文献标题、作者、出版信息、标识符、标签、文件夹、收藏、备注和引用键。
- Document 继续表示可阅读文件，保留其 ID、原文件、阅读进度、定位、批注、聊天、翻译和处理任务。
- 一个文献可有零到多个附件，一个 Document 在论文库中至多归属一个文献。第一阶段只接入已有可读的 PDF / EPUB；其他附件格式留到后续。
- 附件可标记为原文、译文、补充材料或其他，并选择默认打开的主附件。所有附件共用同一文献引用键。
- 文献列表每篇显示一次；没有附件的文献可编辑信息、分类和引用，不能发起阅读或翻译任务。
- 每个文件的阅读进度与笔记维持独立。文献列表显示主附件进度、各附件批注和笔记数量汇总；打开具体笔记仍定位到原附件。
- 书籍库保留原有 Document 工作方式，不强制改造成论文条目。

### 3.2 既有数据迁移与生命周期

- 以增量 schema 迁移建立条目和附件关联。首次升级为每个现有论文 Document 创建一个条目，不自动合并疑似重复论文。
- 原 Document ID、磁盘路径和现有深链接保持有效；批注、聊天、笔记、原文定位与翻译不迁移到其他文件。
- 文献字段迁入条目后以条目为唯一权威来源；旧 Document API 对论文信息的兼容读取与写入通过适配层访问所属条目，避免两份信息各自更新。
- 迁移前在书库内部生成可恢复的数据库快照；迁移事务失败则回滚，重复启动不重复创建条目。升级完成后不承诺直接运行旧版本，回退使用快照。
- 文献合并保留目标条目，移动附件关系，展示冲突字段供用户选择；所有文件及其阅读数据保留，原条目标识保留重定向。原 Document 合并逻辑不能直接当作文献合并使用。
- 移动到回收站不删除原文件；删除单个附件和删除整篇文献是不同操作。条目进入回收站后其附件随条目隐藏，恢复时一并恢复；永久删除沿用现有明确的清理操作。
- 同一文件重复导入应复用现有 Document，不额外生成论文；若已在回收站则提供恢复入口。疑似同一文献的不同文件只提示归并，不静默合并或删除。

### 3.3 PDF 导入与信息整理

- 复用已有多文件导入与后台解析，不另造一套 PDF 解析器。
- 识别顺序为已有标识符、PDF 解析出的 DOI / arXiv 编号、已有在线查询。手动填入的字段始终受保护。
- 没有标识符时保留文件标题，并标出缺少作者、年份等引用信息；允许用户发起标题查询、补入 DOI 或直接编辑。
- 识别失败不影响打开 PDF，也不阻塞其他文件。每份文件有独立结果，可单独重试；沿用自动查询开关，关闭时不发起在线检索。
- 不依靠大模型猜测出版信息。扫描件 OCR 不在这一阶段内；无法提取标识符的扫描件可手动填写或按标题查询。
- 查重沿用现有规则作为候选提示；预印本与正式版本不自动覆盖对方的出处信息。

### 3.4 固定引用键

- 引用键存储在文献条目，而非 PDF 或前端临时状态。复制引用与所有导出格式都使用同一个已保存的键。
- 第一次复制引用、导出或用户主动生成时分配引用键；默认采用首作者、年份和标题词。信息不足时明确提示，并允许使用带条目短 ID 的稳定备用键。
- 一经分配，修改作者、年份、标题、排序、附件或导出范围均不自动改键。
- 数据库事务负责分配和冲突检测。按不区分大小写的规则防止跨工具冲突；自动生成只接受保守的 ASCII 字母、数字、下划线、连字符、冒号和句点。
- 重名只给新条目增加后缀，不重命名旧条目；删除条目后不自动把已用过的键分配给其他文献。
- 允许手动修改，但须展示会影响已有 LaTeX 引用及导出目标；不自动修改用户 .tex 文件，不宣称历史键一定继续可用。
- 两个条目已有不同引用键时默认保持分离。用户明确选择合并后，预览必须选择保留的键，列出不再导出的旧键及受影响的自动导出目标，确认引用影响后才能提交；第一阶段不自动建立 BibTeX 键别名。
- 已导入的合法引用键优先保留；不符合兼容规则或发生冲突时，在导入预览中明确处理，不能静默替换。
- 既有 Reader 的临时导出无法反推出用户曾实际使用的全部键；迁移不承诺修复历史 .tex。若已有 .bib，应先导入并核对键，再建立自动导出。

### 3.5 .bib 导入与导出

- .bib 导入先展示条目、引用键、匹配候选、未知字段和语法问题，再确认写入。匹配优先使用 DOI / arXiv 等明确标识符，标题近似匹配仅作为候选。
- 仅有 .bib 的记录建立无附件文献；后续可以补入 PDF。
- 导入信息不覆盖已手动修改的字段。键冲突必须选择合并到明确匹配的条目、显式改键或跳过；不能用重复键覆盖另一篇论文。
- 导入记录明确匹配到已有条目但使用不同键时，保留已有键为默认；可预览后显式改键或跳过，不能静默用导入键替换。冲突未解决前不写入相关条目。
- 保留未映射字段和必要的 BibTeX 原始值结构，避免把 LaTeX 命令、大小写保护花括号、作者中的机构名称当作普通文字破坏。
- 支持 @string、值拼接与 crossref 依赖的保存和解析；导出选集需要带上必要依赖，缺失依赖明确报错。未编辑的非标准字段不随导出模式自动丢弃。
- 输出模式为 BibTeX 和 BibLaTeX；由模式映射条目类型与期刊、会议、日期等字段，同一条目的引用键一致。默认保持现有 BibTeX 习惯，按项目记住选择。
- 语法错误或无法可靠表达的条目给出位置和原因，保留原导入文件，不接受无提示的数据截断。
- 文献导出可以生成无附件条目；临时导出、复制引用与持续导出复用服务端同一套键分配和序列化逻辑。
- BibTeX 内容始终作为数据处理，不执行其中的命令，不自动打开 file / URL 字段指向的资源。

### 3.6 写作项目与本地自动导出

- 第一阶段复用论文文件夹作为写作项目，不新增独立的项目管理界面。一篇文献可以加入多个项目文件夹。
- 用户为选定文件夹配置一个导出目标：文件位置、是否包含子文件夹、BibTeX / BibLaTeX 模式。默认包含子文件夹，界面明确显示。
- 只有显式配置为 Reader 管理的文件才会持续更新；首次遇到已有文件时先提示选择新文件，或备份后接管。不会自动把人工编辑的 .bib 当作可覆盖缓存。
- 文献信息、项目成员或引用键变化后合并短时间内的连续变更，串行生成该目标的完整快照，并在目标同目录使用临时文件和原子替换。失败时保留最后成功的文件。
- 保存最近一次成功内容的指纹；若目标被外部修改，暂停覆盖并提示用户处理。不能把“自动导出”实现为对用户文件的盲写。
- 记录最近成功时间与错误。Reader 未运行时不更新；再次启动核对并补导出，避免要求应用后台常驻。
- 路径按运行 Reader 服务的操作系统保存和校验。当前 WSL 桌面版使用 Linux 路径，Windows D 盘路径对应 /mnt/d；不能假设 E 盘虚拟磁盘路径等于 Linux 用户目录。
- 同一路径不允许多个导出配置争抢；目录失联、磁盘满、无权限或网络驱动器不支持可靠替换时保留旧文件并显示失败。

### 3.7 Overleaf 流程

- 第一阶段将生成的 .bib 上传到 Overleaf；后续变更后重新上传更新文件。
- 不依赖 Zotero 账户或 Zotero 正在运行，不宣称具有 Overleaf 内置的 Reader 集成。
- 本地自动导出仅更新本地文件，不等同于 Overleaf 自动同步。第一阶段不开放本地服务到公网、不实现非官方登录或自动控制 Overleaf 页面。
- Overleaf 官方支持上传 .bib；内置参考文献管理器集成当前列出 ReadCube、Zotero 和 Mendeley，并属于高级功能。

官方依据（2026-10-21 核对）：

- https://docs.overleaf.com/citing-and-references/creating-a-bibliography
- https://docs.overleaf.com/integrations-and-add-ons/reference-manager-integrations

## 4. 实现约束与边界

- 沿用 React / Electron / Go / SQLite；界面复用 packages/ui，PDF 用 PDF.js，EPUB 保留 Readium 定位和清洗边界。
- 新增文献与引用模块，避免继续扩张 Workspace.tsx 和 Settings.tsx；OpenAPI、共享类型与生成客户端必须同步。
- HTTP API 继续仅回环并鉴权。桌面导出路径由系统选择器取得；浏览器模式保留下载，不能仅凭网页传入任意路径就建立长期写入授权。
- 自动导出授权绑定经校验的服务端目标，阻止路径穿越和通过符号链接替换越过授权目标；复用现有桌面信任边界，不关闭鉴权。
- 原有 document-based CLI、Connector、Zotero / EndNote 导入须在数据模型调整后继续工作，通过适配层关联条目；本阶段不扩充完整的文献管理 CLI。
- 不直接复制 Zotero 主程序代码；本阶段不移植其 Mozilla 运行时或插件体系。新增依赖在实现计划中逐项检查用途与许可证。
- 保留现有翻译体验。固定版式译文 PDF / 双语 PDF 导出、Word 插件、云同步、多人协作、RSS、移动端和通用 CSL 样式管理均不属于本阶段。

## 5. 分步交付

1. 文献与附件数据模型、无损迁移、兼容 API、论文列表与附件管理。
2. 固定引用键及所有既有引用入口统一，含历史 .bib 对照导入的必要基础。
3. 完整 .bib 导入预览、BibTeX / BibLaTeX 导出及字段保留。
4. 文件夹自动导出和桌面路径选择，明确 Overleaf 上传步骤。

每步采用独立可验证的提交，紧密耦合的 schema、API、类型、界面和测试一起交付。第一步完成不代表已经可以独立替代 Zotero；以上四步和整体验收完成才交付这一阶段。

PDF 元数据查询和查重已有实现，仅针对新文献模型补兼容与有证据的缺口，不安排重写。

## 6. 验收与风险检查

- 迁移、失败回滚和重复升级后，原文件校验值、Document ID、批注、笔记、聊天、翻译和原文链接都保持可用；有 EPUB 的混合书库同样验证。
- 同一 PDF 重复导入不产生另一篇文献；不同版本保留独立附件；合并、回收、恢复和永久清理不误删其他文献的数据。
- 同一引用键在单篇、不同批次、不同排序、重新启动和自动更新后保持一致；并发生成重名键、改键、删除后重建均有明确行为。
- 用含中文、机构作者、TeX 命令、花括号、未知字段、宏、crossref 和冲突键的 .bib 验证导入导出；验证 BibTeX / BibLaTeX 各自生成的最小 LaTeX 示例可编译。
- 自动导出验证中断写入、外部编辑、路径失效、磁盘写入错误、启动补更新和多项目隔离；失败不能损坏上次成功文件。
- 在新临时书库完成从多份 PDF 导入到 .bib 导出全过程，不以真实书库做破坏性测试。
- 实现完成运行 pnpm typecheck、pnpm test、pnpm build。当前主目录曾存在 3 项 Pi 会话测试的运行时失败，需先复核并记录基线，不能冒充全部检查通过。
- 按 AGENTS.md 不使用浏览器自动化做视觉验收；交付可启动桌面预览和人工步骤，包含上传 .bib 后在 Overleaf 使用固定键引用。

## 7. 交由实现计划决定的细节

具体 SQLite 表名、迁移编号、API 路径、任务去抖时间、BibTeX 解析库和控件排布由实现计划确定。条目层级、原 Document 标识保留、引用键稳定性、字段保护、自动导出所有权和 Overleaf 边界属于上述设计约束，不能作为局部实现细节省略。
