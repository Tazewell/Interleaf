# Interleaf 原生双语 PDF 导出设计

日期：2026-10-22。状态：用户已确认，实施中；补充按 PDF2zh 方法与自配 API 的要求。

## 已确认的要求

用户选择下一阶段实现类似 PDF2zh 的双语 PDF 导出，要求独立开发、不集成插件，并明确要求两种排版都支持。

- 左右并排：同一张输出页中，左侧原文、右侧对应译文。
- 交替页面：原文第 1 页、译文第 1 页、原文第 2 页、译文第 2 页，依次排列。

本方案将“独立开发”具体落实为 Interleaf 内置排版与导出管线，不安装 Zotero 插件，不调用 PDF2zh、PDF2zh_next 或 BabelDOC 的 CLI、服务或排版核心。可以使用通用 PDF 组合、字体和 Chromium 打印能力；通用库不承担论文翻译或版面重建规则。

用户进一步确认参考 PDF2zh 的具体方法，调用用户自己配置的 API。沿用段落分区、公式占位、按实际字宽回排、公式复位的步骤，由 Interleaf 独立编写实现。

## 目标与首版边界

在现有 Interleaf 桌面版中，把有效中文译文生成为可以独立打开、打印、复制文字的双语 PDF。支持当前 WSL 桌面环境，沿用 Electron、Go、TypeScript、PDF.js 与现有 API 协议实现。可复用适合排版的已有译文；缺失译文或需要公式占位保护的段落由用户明确启动 API 翻译后导出。

首版针对有文字层的横排学术 PDF，支持单栏、双栏、混合图表与公式。尽量保持原页尺寸、栏目、图片、表格和公式位置；不承诺逐字复刻原文字体、字距或任意复杂 PDF 的全部排版。

第一版只接入桌面版导出。浏览器继续使用现有译文 Markdown 和批注 PDF 导出，不显示无法工作的原生双语导出入口。后续扩展浏览器生成能力是独立范围。

不在本次实现 OCR、扫描件自动翻译、其他目标语言、PDF 编辑器、Word 插件或云同步。表格单元格、图内文字、代码、算法和参考文献保持原文；已有图题、表题的有效译文正常排版。原文 PDF 和已有阅读数据始终保留。

## 两种输出的页面规则

使用原 PDF 的可见页面框，并正确处理 CropBox、旋转和不从零开始的坐标。

- 并排模式：每张输出页容纳同一原页及同尺寸译文页，保留原页的物理阅读大小，页面宽度约为两个原页加中缝；不强行缩成横向 A4。混合纸张大小按每组对应页处理。
- 交替模式：每个原页后接同尺寸译文页；N 个选中原页生成 2N 个输出页。
- 使用原始页码与对应关系。页码范围保持原文顺序；默认导出全文，也可选择连续页码范围。
- 每个原页只对应一张译文页。首版不自动增加译文续页，否则无法稳定保持两种模式的一一对应。
- 原文部分保留可见页面内容，优先复用原 PDF 页面内容和矢量，而非把整份文档截图。译文正文也是实际 PDF 文字，可以选择、搜索和复制。
- 原 PDF 的脚本、外部动作、内嵌文件、交互表单、原目录与链接行为不作为本次输出的保留目标；不把主动内容带入新文件。

## 译文页排版规则

复用既有 PDFBlock 的 page、bounds、label、text、image、caption，以及与原文对应的 TranslationBlock。现有 manifest 不保存完整页面几何信息，导出时由 PDF.js 读取真实页尺寸及旋转，并把归一化坐标转换为物理点。

译文页从干净页面重建，不能在仍包含原英文文字对象的 PDF 页上加白色矩形。允许从 PDF.js 的印刷分辨率页面像素中移除待译段落，再把其余视觉区域作为静态背景放入新页；公式从未擦除的像素单独裁取并复位。这样不留下隐藏英文、重复搜索结果与错误复制顺序。

- 正文、标题、摘要、图题、脚注等按现有阅读顺序与栏目放置中文。
- 图片、表格、代码、算法、独立公式等复用原页面对应区域。优先保持原始视觉；需要栅格化的区域以足够印刷清晰度从 PDF.js 重渲染，不直接放大低分辨率缓存。
- 公式优先保留原公式外观，不依赖模型重新识别后再生成公式。已转换为可信数学标记的行内公式可以用现有数学渲染能力；无法可靠恢复的位置必须报告，不能无提示丢掉。
- 参考文献、页眉、页脚和页码使用原内容。图题独立处理，不能同时把相同题注作为图片和中文文字重复写入。
- 中文字体随应用提供并嵌入输出，不依赖用户机器恰好安装了某种字体；字体加载失败或缺字须报告，不能输出方框字。

### 文字过长

排版先使用可读的字号和行距，测量真实文字尺寸，再在不覆盖图表、公式和相邻栏目前提下使用可用空白。必要时有限缩小字号，首版建议正文不小于 9 pt。

达到最小字号仍无法容纳时，该次导出失败并列出原页码、段落和原因；不截断、不隐藏溢出、不无限缩小字体，也不把失败页悄悄换成英文。用户可选择其他页码范围或调整译文后重新导出。

超长译文的续页模式、自动改写压缩译文以及大规模重新流式排版不属于首版。若真实样本表明 9 pt 与原页对齐无法兼顾，实施前应通过受限排版试验修订该方案，不以放松验收伪装完成。

## 译文与任务的一致性

导出使用一个冻结快照：文档原始内容标识、版面、页范围、成功保存的译文、渲染选项和字体/导出器版本。开始后发生新的翻译或重译，不混入正在导出的文件。

- 只接受 sourceHash 与当前版面原文一致且状态为 complete 的可见成功译文；可沿用重译期间仍有效的上一版成功结果。
- 不导出流式半成品。预检报告缺失译文及需要公式保护的段落数量，用户点击“翻译并导出”后才调用配置中的 API 地址、密钥和翻译模型；不回退到 CLI。完整响应、段落对应与公式占位符全部验证后才排版。
- 公式占位符必须恰好保留一次；缺失、重复或未知占位符均使对应段落失败。导出专用翻译不覆盖阅读器中已保存的译文；可复用译文仅限来源一致、完整且不需要再次解释数学标记的内容。
- 没有可翻译文字的页面必须明确列出。用户可选择标记为保留原文，或者取消/排除这些页；不把扫描正文默认为已翻译。
- 公式、参考文献及其他按规则保留原文的块不因没有中文译文而被误报为待翻译。
- 重试可以复用与快照完全相同的中间结果；缓存不能只按 documentId 或页码命中。选择不同模式不改变同一译文页的内容。

## 用户操作与文件保存

在现有导出入口增加“导出双语 PDF”，使用 packages/ui 的现有对话框、按钮和选择器。设置仅包含两种排版、页码范围以及“完成后保存到文献附件”；默认并排、全文、不自动添加附件。

预检展示原页数、输出页数、缺失译文/无文字页及可行动错误。确认后显示准备、排版、组合和保存等真实阶段；按已完成页数显示进度，允许取消。当前阅读器保持可用，不因导出关闭文档。

- 生成成功后使用原生保存流程，文件名区分并排与交替。取消保存不覆盖用户文件。
- “完成后保存到文献附件”只对已归属 PaperItem 的 PDF 显示。需要生成验证成功后再次显式提交到书库，由服务端创建真实 Document，并关联到原文献的 translation 附件角色；不另建一篇文献、不改引用键和主附件。
- 两种模式分别是独立附件；重复保存同一个冻结结果时复用相同内容的已有附件，不制造重复条目。
- 下载、保存和挂附件失败均明确显示；一次成功不能掩盖另一个用户勾选操作的失败。保存取消后不自动挂附件，避免用户取消后仍写入书库。
- 不自动删除旧译文 PDF。更新导出生成新结果，旧附件的处理由用户决定。

## 实现方向与安全边界

Go 管理预检、冻结快照、API 翻译、任务取消和书库生命周期；processor 中独立 TypeScript 模块用 PDF.js 提取与渲染、用通用字体库测量、用 PDF-LIB 写入真实文字并组合页面。直接生成 PDF，避免新增 HTML 打印窗口和另一套浏览器生命周期；Electron 负责原生保存选择器。不要求用户安装 Python、Zotero 或额外 PDF 翻译服务。

具体模块路径、库版本、字体文件和许可证、任务 API、持久化表及缓存清理策略在实施计划中锁定。新增依赖必须证明用途；PDF.js 仍负责 PDF 读取、渲染与坐标解释，EPUB 内核不改动。

- 译文和原始文档均为不可信数据。打印模板只接受经校验的数据和安全静态样式，不执行其 HTML、脚本或外部资源。
- 排版处理器不执行文档或译文 HTML、脚本、链接；不加载远程图片或字体。路径只来自服务端持有的文档、任务目录与应用资源，渲染器不传入任意文件路径。
- 本地 API 保持回环鉴权；渲染器不能传任意路径让服务端或主进程写入。最终保存路径由原生选择器决定。
- 导出临时文件与用户原文件分开，取消/失败只清理本任务拥有的临时产物，不修改原文、译文、批注、笔记或其他任务结果。
- 文档移入回收站、永久删除、书库迁移和应用关闭应取消并等待关联导出任务退出；不能在删除后迟到创建附件。
- 进程异常后保留已有成功文件，未完成任务标记中断，重试重新核对快照。

## 测试与验收

1. 页面配对：N 页并排为 N 页、交替为 2N 页，页码范围顺序正确；不同尺寸、90/270 度旋转、CropBox 偏移均验证。
2. 内容保全：中文文字可复制与搜索，原文和译文没有隐藏重复文字；原文可见内容、图表、公式、图题不遗漏，引用键及原始文档校验值不变。
3. 排版边界：真实单栏、双栏、密集图表、脚注、公式与长译文样本。验证测量、字号下限、碰撞与失败页报告；不能仅测试程序返回了 PDF。
4. 输入快照：未完成翻译、旧 sourceHash、进行中的重译、损坏资源和无文字页面均有明确行为；并发翻译不混入文件。
5. 生命周期：取消、保存取消、磁盘/字体/渲染失败、重复挂附件、文档回收或删除、应用退出及书库迁移均不产生半文件或迟到附件。
6. 真实 PDF 测试：重新打开生成文件，核对页数、尺寸、字体、文字及图片；使用标准 PDF 工具渲染为图片检查布局，逐页检查所有测试样本的输出，修复溢出与重叠。此流程是 PDF 文件质量检查，不使用浏览器自动化做产品视觉验收。
7. 运行 pnpm typecheck、pnpm test、pnpm build，并在隔离临时书库中完成 WSL 桌面实际导出、保存、打开和附件关联。给用户两种可下载 PDF 样本与人工操作步骤，不用真实书库做破坏测试。

## 当前代码依据

- apps/server/internal/reader/processing.go：PDFBlock 与 layoutManifest。
- apps/server/internal/reader/translation.go：原文哈希、可翻译块与可见成功译文。
- apps/processor/src/layout.ts、layout-worker.ts：版面类别、坐标、素材区域与 PDF.js 渲染。
- apps/web/src/readers/pdf-export.ts：已有原文批注 PDF 导出，保持独立兼容。
