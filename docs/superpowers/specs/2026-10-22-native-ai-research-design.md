# Interleaf 内置 AI 与主题研究设计

日期：2026-10-22。状态：用户已确认并要求制定实施计划；独立可实施性检查未发现重要未决问题。本文是产品与架构设计，不代表功能已经实现。

## 用户已明确的目标

Interleaf 通过用户配置的 API 地址、API Key 和模型提供 AI 功能，不再关联或依赖 Codex、Claude Code、Kimi 等外部 Agent。Interleaf 自己管理会话、上下文、工具调用和任务。

除单篇论文的阅读、问答、翻译和总结外，可以总结一个主题文件夹下的文献，比较研究方法与结论，探索研究 idea。可以按需联网搜索相关论文，核查候选 idea 与已有工作的重合。

以已经完成的双语 PDF 版本为开发基础，保留文献管理、引用键、LaTeX/Overleaf 使用流程、批注、笔记和双语 PDF 导出。开发基线为 `codex/bilingual-pdf-export` 的 `1fb835dc83cfaf8f573f72ecb94a8e0bb8eb735a`；本设计在独立分支 `codex/native-ai-research` 中编写，尚未合并 main。

## 预期使用方式

1. 用户在「AI 设置」填入协议、API 地址和密钥，添加或选择问答、翻译、图片理解模型。研究默认使用问答模型，也可单独指定。无需额外 Agent 安装、登录、账号订阅或 Agent SDK。
2. 打开主题文件夹，进入「主题研究」。可提出问题、生成主题综述、比较方法，或探索 idea。研究范围明确显示论文数量、子文件夹是否包含、可读全文及仅元数据的数量。
3. AI 检索并读取范围内的论文，展示实际进度、引用和未能读取的篇目。全文事实可点击回到具体论文的页码/段落；摘要来源显示为摘要。
4. 用户为该研究打开「允许联网」，或直接提出找论文/查新要求，AI 可以在本次授权范围内自主选择关键词、搜索和补读公开论文。每次请求不重复弹窗；允许随时关闭联网或取消任务。
5. 综述、对比表和 idea 保存在主题研究记录中，可继续追问、修改及导出 Markdown。联网发现的论文进入候选列表，用户选择后通过现有导入流程加入书库。

## 交付范围与成功标准

这是一次完整的架构与功能改造。实现可以按内部 AI 基础、主题研究、联网检索/查新分段提交，但最终交付必须包含三者，不把只改设置页或只做单篇聊天作为完成。

| 能力 | 应有行为 |
| --- | --- |
| 内置 AI | 正常问答、翻译、总结、图像理解及双语 PDF 都通过 Interleaf 的 API 服务，不触发外部 Agent/Pi 进程 |
| 主题综述 | 按研究问题、方法、数据/评测、发现与局限综合；同意、冲突与尚无证据的部分分开；显示分析覆盖面 |
| 跨论文问答 | 检索文件夹内多篇原文、比较并引用；仅来自其他论文的结论不能误挂到当前论文 |
| Idea 探索 | 从已有结果与缺口生成少量候选方向，用户可继续展开其中一个；每个方向包含机制、假设、最近相关工作、最小实验、基线/消融、可能失败条件和资源估计 |
| 联网找论文 | 真正调用学术检索接口，去重、显示年份/来源链接/摘要与获取状态；搜索失败不能伪装成零结果 |
| 创新性核查 | 将 idea 拆为可检索的技术主张，比较最近相关工作，标明重合/部分重合/尚未找到/证据不足，记录检索范围和日期 |
| 持续研究 | 保留完整可见对话、已完成报告和证据版本；新增或替换文献后可增量分析，旧报告标记需更新 |
| 独立运行 | 未安装任何外部 Agent，且没有 Pi worker 的环境中，上述功能及已有双语 PDF 仍可使用 |

## 设计者的默认选择

以下是实现建议，不冒充用户已逐项指定；审阅时可调整。

- 第一版使用现有 Go 后端实现模型/工具循环，复用已存在的 OpenAI Chat Completions 与 Anthropic Messages 直连、流式解析和文档工具。移除 AI 运行链路中的 CLI 适配器、Codex 持久 thread、Kimi ACP、Claude CLI 及 Pi 调度/依赖。PDF 处理所需的 Node worker、Electron 和非 AI 的 `reader` 命令行仍保留。
- 第一版采用一个主要 API 连接，并按用途指定模型；研究模型留空时继承问答模型。允许自定义兼容端点和用户明确配置的本地模型端点，不内置训练或托管模型。支持未配置视觉模型时的纯文字研究。
- 文件夹研究默认遵循当前书库对子文件夹的包含设置，并允许在研究范围中调整；默认选择每篇文献的可读原文附件，避免把译文附件当成第二篇论文。
- 联网权限归研究会话，默认关闭；用户明确提出联网查新/找论文即开启该次任务权限。普通本地综述不会自行调用论文搜索服务。模型 API 请求与论文检索联网是两类不同的网络行为，界面不将关闭论文联网描述为完全离线。
- 第一版内置 arXiv 与 Crossref 主题检索，无需用户另外配置搜索密钥；可读取检索返回的公开论文链接及用户明确提供的公开论文链接。复用现有 scholar 解析/导入基础，扩展其“查单篇”能力为“查相关工作”。OpenReview 等已有解析入口可用于读取候选，但不把尚未实现的全站检索列为搜索覆盖。其他检索服务作为以后扩展，不强迫用户先办第二套 Key。
- 论文候选默认不自动导入、不改文件夹和标签、不改原文/引用键。选中导入后走现有重复检测与文献事务；同一论文的预印本/正式版显示关联，不因标题相近自动合并。
- 第一版采用原文 FTS 检索、关键词改写、逐篇结构化证据与按问题补读；不要求配置 embedding 模型或运行独立向量数据库。实现者可调整内部检索排序，但不得用若干摘要冒充全面阅读。

## 内部结构与职责

保留 React/Vite、Go/SQLite、Electron、PDF.js 和 Readium 边界。API 请求、密钥使用、模型会话与网络工具均由 Go 后端管理；renderer 不运行模型调度，不接收服务端已保存的原始 Key。

### 配置与模型路由

AI 设置使用「连接」「问答」「翻译」「图片理解」「研究」等用途，移除 Agent SDK 选择、安装探测、登录和 CLI 相关错误。设置提供连接/流式能力检查、模型列表获取及手填模型 ID；模型列表失败不能清除已配置模型。图片或工具能力不足时明确降级为对应的文字模式，不能声称模型已经看过图。

每次任务冻结端点、协议、模型、用途、必要参数及凭据引用。连接或模型变化使后续新任务使用新配置；已有任务不能中途拼接另一模型。完整响应正常结束、输出结构与来源校验通过后才保存成功结果；已可见的部分输出不自动接备用模型或追加兜底答案。

密钥只在配置提交时送入本地鉴权 API，读取配置只返回 hasKey/脱敏信息；不进入文献、提示词、工具参数、日志、诊断或研究导出。沿用仅服务端可读、原子写入的本地设置保护，明确不依赖外部 Agent 的凭据文件。可用系统凭据库属于以后增强，不以不存在的加密能力描述第一版。

### 会话、工具与上下文

Interleaf 拥有一个可取消的模型/工具循环，支持流式文字、可选图片、结构化工具调用及严格完成信号。只执行注册工具，校验参数、范围、次数和输出大小；文献/网页/模型返回的文字不是命令。

沿用 SSE 的 draft/delta/activity/reasoning/done/error 等现有前端语义，保留增量文字/图片路径和“完成并保存后才 done”的约定。部分输出不被写成成功回答；重开或断线时先查询同一请求是否已完成，不自动重发可能付费的请求。原来针对外部 Agent 的契约说明随代码更新为内置 AI 契约。

完整对话保存在本地，活动模型窗口按预算保留完整的工具调用/结果组，旧窗口压缩为有来源 ID 的检查点；压缩失败不删除完整历史、不截断用户问题或伪造成功。压缩内容属于派生记忆，详细结论仍可补读原文核查。当前已有 API 对话/工具/压缩实现可抽取复用，不能照搬 Codex/Pi 的私有续接状态。

工具分为单文献读取、研究范围读取、公开论文检索/读取。研究首版的模型工具只读书库和候选资料；写入研究记录由受控任务流程执行，导入文献由显式用户动作执行。不向模型开放 shell、任意文件读写、任意 SQL 或删除/移动书库资料。

### 主题范围与证据

主题研究拥有稳定 ID，绑定书库中的文件夹路径及是否包含子文件夹，而不是以当前页码或 UI 文本做会话主键。重命名/移动文件夹同步更新绑定；删除文件夹时将已有研究记录标为范围已移除，保留用户研究笔记，不静默删除成果。

每次研究创建范围快照：成员 PaperItem ID、所选原文 Document ID、文件/解析版本及可用元数据。排除回收站，按文献而非附件计数；缺 PDF/EPUB、解析失败、仅元数据、无文字页等有单独覆盖状态。对话可显示当前范围变化，已开始的一轮不混入后来加入的论文。

对每篇可读论文提取问题、方法、关键假设、数据集、实验设置、发现与局限，并保留支持这些字段的证据定位。不能从标题补造论文细节；只有摘要的论文只能形成摘要级条目。结构化条目按文献内容、解析版本、模型/提示版本缓存；原文、模型或提取协议变化时相应失效。

跨文献综合先利用目录/证据条目筛选，再按问题补读原文及必要图表，最后形成对比；大文件夹分批及分层综合，显示总数/已分析数/失败数/尚未完成数。预算不足时保存明确的部分进度，允许继续剩余篇目，不静默只取前若干篇并声称覆盖全文件夹。

来源记录包含本地/联网类型、论文身份、文档/网页版本、位置、读取时间、内容摘要 hash 和实际读取范围。PDF 使用页码/块；EPUB 使用原生章节/位置；网络摘要、HTML 段落和 PDF 页分别表达，不能伪造统一页码。来源标记必须由本次已读证据验证，点击时再次检查内容版本；失效来源显示状态，不跳转到同页码的其他内容。

永久删除或替换原文后，使相应证据缓存失效并取消相关读取任务，清理该文档的临时全文/页图。已保存的跨论文研究笔记和报告仍为用户资料，标记其中来源已移除，不能通过缓存绕过删除继续读取原文。

## 按需联网与创新性核查

### 检索、读取和来源覆盖

网络检索工具接收查询、年份等过滤条件和分页限制，返回规范化候选：标题、作者、发表/更新日期、DOI/arXiv/来源 ID、摘要、公开原文链接、来源及获取时间。不把模型编造的引用当作搜索结果，也不以同名论文自动替换已有证据。

先以明确标识符去重、关联预印本与发表版本，再谨慎显示可能同文献条目；年份过滤及版本日期应在记录中可核查。优先读取实际论文、正式论文页面或作者公开版本；只有摘要时标明证据层级，缺少方法/实验正文就不能声称已验证具体差异。

使用独立于模型连接的 HTTP 客户端，不把模型 API Key 发给检索/下载站点。允许公开 HTTP(S) 论文来源，拒绝本机/私网/链路本地和非 HTTP(S) 地址，校验 DNS 解析、实际连接地址与重定向目标，设置响应、文件大小和超时限制。用户显式配置的本地模型 API 不受“公开论文下载”地址规则误伤。网页去除脚本/主动内容，PDF 进入现有隔离解析流程；不得绕过登录、付费墙或防访问限制。

全局共享每来源的限速、并发和 Retry-After/退避策略，支持取消等待；arXiv 单连接、间隔至少三秒。公共检索接口超时、限流、不可用时记录失败来源，保留本地研究和已有结果，提供人工重试。不能自动改用未配置的收费服务、外部 Agent 或未经实现的搜索来源。

联网查询可能包含用户的研究关键词；设置说明这一点。模型只应生成完成该问题所需的简短学术查询，不向搜索源提交整个本地 PDF、私人笔记或无关历史。用户可以查看实际查询，关闭联网后阻止尚未发出的网络工具并取消活动论文下载，已有本地资料仍可用。

### Idea 与查新结果

探索流程依次完成：明确问题/约束 → 总结已有证据与瓶颈 → 提出候选机制 → 拆解待核查主张 → 执行同义词/相邻领域/方法组合/具体组件检索 → 读取最近相关工作 → 修订候选与实验计划。

每个候选包含：针对的具体问题、相对已有工作的改动、为何可能有效、机制/可实现模块、必要假设、最小验证、比较基线/关键消融、预期观察和推翻条件，以及有依据的资源估计或明确未知项。首版不自动运行训练、复现实验或自称结果已证实。

查新表逐项比较「本候选主张」「已有工作对应做法」「重合与差异」「可定位证据」「尚未核实内容」。结论状态为发现高度重合、部分重合、当前检索未找到或证据不足；不生成“保证原创”“全网首创”或没有校准依据的创新概率。

保存查询词、来源、日期/年份范围、返回结果/失败来源、已读全文/摘要覆盖和被排除候选的原因。只搜本地时明确本地范围；联网失败或只有摘要时明确不足。报告可以建议下一步核查实验设置、代码或未获取全文，不以论文标题相似度代替方法比较。

## 研究状态、任务与资料保存

SQLite 持久化主题、会话消息、任务、范围快照、结构化证据、网络候选/读取记录、引用及用户保存的报告。具体表名/DDL 由实施计划定义；不把新研究资料塞入某一篇论文的 messages 或笔记而混淆所有权。

长任务以阶段与可复用成功单元推进：准备范围、逐篇分析、补充检索/读取、综合/查新、完成。只有完成信号及证据校验成功的单元可作为检查点；批次失败/取消不伪装整项完成。已保存的成功报告不被失败的新一轮覆盖；新结果生成新修订。

任务拥有请求 ID/幂等键，重复点击或 start 响应丢失先查同任务；恢复不会不经用户操作再次付费。可暂停/取消并继续剩余单元，重启时将进行中任务标为中断并显式提供继续；不得在启动时自动重放模型或网络调用。保持每主题同一时间一个修改性研究任务，跨主题并发有全局限制；详细预算/超时/工具次数由实施计划依据现有协议制定，并显示触顶/未完成情况。

模型/参数/资料快照变化后不能盲目续接旧尝试；明确需要新一轮，仍保留历史成功结果。用户关闭一次普通聊天取消该次请求；已显式创建的长研究任务可以在应用内后台继续并可从任务状态取消。退出应用、迁移书库或删除相关资料时取消并等待模型 HTTP、下载和解析工作结束，清理仅本任务拥有的临时文件。

## 旧版迁移与兼容

- 从已有 `AIConfig.API`、按用途的模型和 API Key 迁移到内置连接；旧 TextAPI/ImageAPI 是候选来源，只有配置映射无歧义时迁移，不能暗中选择付费端点或把不同协议的模型混在一起。迁移无主要连接时显示待配置，不探测本机外部 Agent。
- 保存旧配置备份及版本，原子迁移；不读取 Codex/Claude 等凭据或删除已安装的外部软件。用户现有 API Key 不因升级空覆盖。
- 可见历史问答、来源、推理展示字段、笔记和译文保留。外部 Agent/Pi 的私有线程与协议状态不复用；可见历史按现有语义重建模型上下文，无法验证的旧来源不升级成已读证据。
- 替换 `translationService` 中对 Codex 连接的硬断言和其他启动/能力检测依赖，不只改 primary 字段。现有摘要、分类、公式转换、自动翻译和双语 PDF 都使用统一用途路由；双语 PDF 的冻结、完成、保存及附件事务边界保持。
- 清理外部 Agent 连接 UI、后端调用/探测、Pi runtime/build/package 依赖与对应失效测试/说明；新分发包无需这些 AI 运行时。保留原文、EPUB/PDF 阅读器、非 AI 文献导入/导出、书库本地 API 和 `reader` 客户端。
- 保留已有文献/文件/引用键及 BibTeX/BibLaTeX 导出设置。主题报告可引用本地文献键；Markdown 导出带来源链接，导出不改书库。

## 不属于本轮范围

本地训练或托管大模型、自动跑实验/写训练代码、定时监控新论文、通用网页搜索引擎或全网爬虫、付费墙获取、OCR、共享云研究空间，以及没有证据的学术创新保证。通用的本地兼容模型 API 可以配置，但不包含模型下载/部署。

## 验证与交付要求

1. 新配置、密钥不回显/泄漏、模型角色与旧配置/历史迁移覆盖回归；无外部 Agent/Pi 环境下端到端正常工作，旧 provider 不会被隐式选用。
2. 两种 API 协议的文字/工具/图片流、正常结束与截断、畸形工具参数、取消、超时、压缩和失败恢复均测协议边界；可见半成品不保存成功，不接备用拼接。
3. 单篇阅读、翻译、概要、图像理解、分类、双语 PDF 的现有功能完成适配回归；已有双语 PDF 两种布局、公式/字体/9 pt、取消和附件/原文保全继续验证。
4. 文件夹成员/子文件夹、同文献多附件、仅元数据/解析失败、版本变化、重命名、删除、增量分析和大量篇目分批覆盖数据/lifecycle 测试；未读取范围不冒充完成。
5. 多篇有已知冲突结论的自有论文 fixture，验证跨论文引用身份、原文定位与覆盖统计；伪造/混淆来源被拒绝，摘要与全文级证据不混用。
6. 本地模拟 arXiv/Crossref/论文来源覆盖真实 HTTP 解析、分页/去重/版本、速率/退避、部分来源失败、SSRF/DNS/重定向、公开全文读取、取消/退出/迁移等待和不自动导入；关闭联网不能调用这些服务。
7. 至少一组“主张已被相关工作覆盖”的确定性查新 fixture，报告必须呈现重合证据；另一组仅摘要或检索失败 fixture 必须给不足结论，不得生成肯定创新判断。模型输出 mock 与真实推理质量分开报告。
8. 测试幂等任务、断线查询、用户取消、重启中断、继续成功单元、预算触顶、保存原子性及已有成功成果保全；执行前后核对真实样本书库的原文、引用键、阅读译文、批注和笔记。
9. 最终执行 `pnpm typecheck`、`pnpm test`、`pnpm build`，在 E 盘承载的 WSL 环境建立隔离预览与样本，提供用户 API 配置/主题综述/查新人工步骤。禁止浏览器自动化做界面视觉验收；真实 API/在线服务的可用性烟测与 mock 覆盖分别注明。
10. 文档、OpenAPI/生成类型、实现与测试一致，按可验证功能小步提交，不推送/合并/发布，除非用户后续明确要求。实现前先依据获批设计制定实施计划。

## 已核查的代码基础与外部接口

- `apps/server/internal/reader/{connections,generation,api_agent,api_stream,api_anthropic}.go`：现有多 Agent 配置及 API 传输；`pi_agent.go` 和 `apps/agent` 是需要替换的会话调度依赖。
- `document_tools.go`、`document_conversation.go`、`api_chat_tools.go`、`api_conversation_compact.go`：单文献读取/证据、持久对话与严格流完成/工具协议，可复用其有效边界。
- `apps/server/internal/scholar`：已有 DOI/arXiv/OpenReview/标题解析及公开 PDF 导入；主题搜索、研究证据保存、共享限速与 DNS/连接级保护需要新增或补足。
- `packages/reader-core/src/papers.ts`、`apps/web/src/papers/model.ts`：PaperItem/附件与文件夹含子级的现有语义；当前没有稳定的主题研究实体。
- `bilingual_pdf*.go` 与 `docs/native-bilingual-pdf*.md`：上一阶段已完成的 API 翻译/原生双语 PDF 及实际验收边界，必须保留。
- [arXiv API 手册](https://info.arxiv.org/help/api/user-manual.html)及[官方使用要求](https://info.arxiv.org/help/api/tou.html)：支持查询/分页，当前 legacy API 要求单连接且至少三秒间隔。实现时保留适配器与限速可调整能力。
- [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)：公开元数据搜索无需注册，可获取 DOI/文献信息，元数据存在并不意味着可读取全文。上述官方资料于 2026-10-22 核查；本轮未用用户文件或密钥进行真实研究检索。

具体模块拆分、数据库 DDL、端点名称、资源预算及测试文件由后续实施计划确定。产品范围、证据可信性、用户数据与生命周期约束不得借由模块拆分而缩小。
