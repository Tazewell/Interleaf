# 阅读滚动性能采集

该工具只服务指定的生产构建，在页面注入本地采集面板，不改变安装版或正常开发入口，不上传数据。报告不记录论文文本、标题、网址或认证令牌。

先构建前端：`pnpm --filter @interleaf/web build`。后端启动后，从仓库根目录运行：

```powershell
node apps/web/scripts/reading-performance.mjs --web apps/web/dist --backend http://127.0.0.1:17840 --port 65008 --label after
```

用当前后端的启动令牌打开该端口（保留启动地址的 `#token=…` 部分，只替换端口）。认证不变，未认证请求仍会被拒绝。服务只监听 127.0.0.1。关闭该 Node 进程即可结束采集服务。

## 对照方法

1. 修改前保存完整生产构建目录，修改后另行构建；分别传给 `--web`，使用 baseline/after 标签。
2. 相同论文、译文、批注、主题、视口、DPR、缩放及起始目录项。先等待加载完成，重复一次相同滚动作为热身。
3. 分别选择原文、对照不同步、对照同步条件；切换实际阅读模式/同步开关后，再选择对应的采集条件。条件选择器只标记报告，不改变阅读模式。
4. 点击开始记录，执行相同次数和方向的真实滚轮/触控板操作，立即停止。复制“采集结果”中的 JSON。每种条件至少重复三次，冷加载与热缓存分开比较。
5. 不切换窗口、不调整尺寸；这些变化会使报告无效。只比较滚动次数、可见区域和采样条件匹配的结果。

## 指标与限制

- `frameCallbacks`：滚动事件及其后 200ms 窗口内开始的 rAF 回调间隔 p50/p95/max，以及超过参考 60Hz 预算 1.5 倍的次数。包含跨过窗口结束边界的最后一个间隔，避免漏记长停顿，后续空闲帧不计入。这是主线程调度指标，**不是实际呈现 FPS，也不是准确丢帧数**；高刷新率设备应结合实际刷新率解释。
- `longTasks`：整个记录窗口的主线程长任务，包含工具、浏览器及其他脚本开销；记录中闲置时间不同会影响比较。
- `mutations`：阅读应用根节点的 DOM 增删与属性变动数量，并不等于重排次数。
- `layoutShiftSum`：原始 LayoutShift 分值累加，包含用户输入后的变动，不是网页标准 CLS 得分。
- `scrolls`：原文、译文及其他区域的事件数；同步开启时包括程序跟随事件。

本地采样用于定位问题和排查回退，不能单凭一次 p95 下降宣称性能提升。真实呈现帧、栅格化、GPU、强制布局和各调用栈成本仍须在 Chromium/Electron Performance trace 中核对。采集面板和 CUA/开发者工具自身也会扰动结果。

不在正常阅读中全局关闭 PDF 文本层，不用 `will-change` 或平滑动画掩盖同步跳动。变更后仍需人工验证选区、搜索、批注、图引用及两侧阅读位置。
